### R01 · P1：最终参数被覆盖，核验仍显示 VERIFIED

**位置：** `src/autogrid.py:238`、`src/autogrid.py:247`、`src/autogrid.py:1160`。

生成后的控制回读已经收集，但 `verify_control_readbacks()` 只使用 setter 刚执行后的 `control_results`。用户请求参数、setter 后回读一致，而网格生成过程将参数重算或覆盖时，最终核验仍显示 `VERIFIED`。

本次协议桩复现：请求 200，setter 后回读 200，生成后回读 0，结果仍为 `VERIFIED`、核验回读仍为 200。这验证的是宿主核验逻辑，不代表 AutoGrid 必然重置该桩所用的优化参数。真实可达性另有当前项目实机记录：`docs/MESH_CONTROL_VALIDATION_RESULTS.md:568` 记载 `blade/b2b.default.boundary_layer_width` 在生成后被统一改回 `0.001692339 m`。

**修复：** 保留应用阶段证据，并用生成后回读给出最终核验结果；复用现有比较函数，对生成后不匹配、读取异常、无 getter 分别标记 `MISMATCH`、`READBACK_ERROR`、`UNVERIFIABLE`。保留既有“生成成功与控制核验异常分开记录”的契约。

**必要回归：** setter 后匹配、生成后不匹配/报错，不能继续显示最终 `VERIFIED`。

**证据：** `runs/review_20260912/core_controls/results.json` 的 `post_generation_reset`。

### R02 · P1：报告中的非法质量数据可被忽略，仍判 PASS

**位置：** `src/quality.py:13`、`src/quality.py:121`、`src/quality.py:542`。

统计行正则只识别普通数字和科学计数法，不识别 `NaN/Inf`。把一份其他指标合格报告的 `Average wall distance` 替换为 `NaN` 或 `Inf` 后，该行直接被跳过；因它不是八个必填字段之一，结果仍为 `PASS`、`accepted=true`、`quality_validation=VALID`。

另一个同类遗漏是只校验 Entire Mesh 的扁平指标：逐叶排统计中已解析出的非有限值会在序列化前变成 `null`，但不会使校验失败。本次在逐叶排统计中放入 `Average Wall Distance : 1e999`，也得到 `PASS/VALID`。这与 `docs/QUALITY_CRITERIA.md` 和 `docs/PLAN.md` 所要求的“检查所有已提供的统计值”不一致。

**修复：** 在识别到质量统计字段后保留非法数值及字段来源，或直接积累解析错误，不能把非法字段当成未提供；对全局及各叶排的已提供统计执行同一领域校验。非法数据返回 `UNKNOWN/accepted=false`，原文与字段路径保留，JSON 数值仍安全输出为 `null`。保持现有质量阈值不变。

**必要回归：** 一个非必填字段的 `NaN/Inf`，以及一个逐叶排非有限值，应得到带字段位置的 `UNKNOWN`。

**证据：** `runs/review_20260912/core-review-evidence.json` 的 `optional_nan`、`optional_inf`、`row_nonfinite`；对应原始 `.qualityReport` 同目录保存。

### R03 · P1：Worker 快速重启后，旧任务可能永久卡在 RUNNING

**位置：** `platform/mesh_app/worker.py:468`。

Worker 仅首次 `run_once()` 时回收心跳过期任务。若故障后在默认 30 秒过期阈值内重启，旧任务第一次检查仍未过期，会被跳过；之后主循环不再调用这项恢复。失去执行进程的任务继续占用并发槽，用户无法等到终态，会话也无法冻结。

**修复：** 使旧任务回收在后续调度循环中也能触发；依据已有心跳、进程和 Worker 所有权判断，避免终结仍活跃的本机任务。可采用受现有心跳间隔约束的周期检查，无需增加新的调度框架。

**必要回归：** 首次恢复时未过期、后续时间推进后过期的旧任务，能自动到达失败终态并释放容量。

**证据：** `runs/review_20260912/backend/reproduction_results.json`。

### R04 · P1：后处理失败后预览永久 PENDING，导致会话无法冻结

**位置：** `platform/mesh_app/worker.py:1088`。

后处理超时或异常退出时，终结逻辑更新 `postprocess_status=FAILED`，却没有同步预览状态。可以留下 `SUCCEEDED + FAILED + preview_status=PENDING`。界面持续等待预览，冻结返回 `409 PREVIEWS_STILL_PENDING`；重启恢复又不处理已经 `FAILED` 的后处理，因此无法自然结束这个状态。

**修复：** 在同一事务中，将后处理失败运行仍为 `PENDING` 的预览同步终结为已有的 `FAILED` 状态并保存错误原因，manifest 接口返回明确失败信息；保持网格生成终态不变，不覆盖已经 `READY/UNAVAILABLE` 的预览。已积累的 `postprocess_status=FAILED AND preview_status=PENDING` 记录需要做一次针对性状态修正。不要直接放行所有仍在处理的 PENDING 任务。

**必要回归：** 超时和异常退出后，生成结果仍保留，预览不再等待，满足其他条件的会话可以冻结。

**证据：** `runs/review_20260912/backend/reproduction_results.json`。

### R05 · P1：数据库路径含 # 时，备份可能成功生成空数据库

**位置：** `platform/mesh_app/backup.py:40`、`platform/mesh_app/backup.py:186`。

代码直接拼接 SQLite `file:` URI，未对文件路径编码。Windows 合法目录名中的 `#` 会被解释为 URI 片段，后续路径及 `mode=ro` 不再是原意，可能打开并新建错误路径的空数据库。SQLite 的 `quick_check` 对空数据库也能返回 `ok`，因此备份命令会报告成功。

本次使用包含 `#` 的隔离数据目录，源库具有真实平台 schema v2 和一个会话；完整备份流程成功返回，但备份数据库零表。该备份无法恢复原平台数据。

**修复：** 用 `Path.resolve().as_uri()` 生成经过路径编码的 URI，再追加 `?mode=ro`；两处打开入口使用相同方法。继续复用现有备份和完整性检查，不需要另建备份框架。

**必要回归：** 含 `#` 的源路径通过实际备份流程后，会话记录及数据库表被保留。

**证据：** `runs/review_20260912/backend/backup_uri_result.json`。

### R09 · P2：运行结束后重新读取外部输入，来源记录与实际网格不一致

### R12 · P1：经验旧草稿使用新版本号保存，绕过并发保护

### R14 · P2：质量比较把 null/空值转换成 0，给出虚假差值

**位置：** `platform/ui/src/features/compare/qualityDelta.ts:60`。

`Number(null)` 和 `Number('')` 都得到 0，随后通过有限数值检查。内核对非法/非有限统计会输出 `null`，成功运行的质量也允许为 UNKNOWN，因此这是实际可达的比较输入。本次 A 的指标为 null、B 为 12，比较返回 `left=0, right=12, delta=12`，将未知值伪造成零。

**修复：** 转换前排除 null、undefined 和空白文本；只比较两边都有有效有限数值的指标，其余显示缺失或不参与差值。

**必要回归：** null 对有限值不产生数值差值，真正的 0 仍正常参与比较。

**证据：** 前端定向复现 F04；真实上游 null 路径也由现有 `tests/test_quality.py:320` 覆盖。

### R15 · P2：登录过期后直接保存，401 不会触发重新登录

**位置：** `platform/ui/src/app/queryClient.ts:6`、`:25`。

全局只在 QueryCache 的查询错误处理中恢复认证，mutation 没有同等处理。用户停留在无活动任务的页面，登录过期后直接保存经验、创建分支或冻结，会反复收到“请先登录”，但没有登录表单。匿名健康轮询不能补救这个状态。

本次用真实 AuthGate 和全局 QueryClient 复现保存返回 401：认证查询仍仅调用一次，登录界面没有出现。

**修复：** MutationCache 或统一 API 错误处理在 401 时同样使认证查询失效；与现有查询路径保持一致，并保留未提交草稿，避免重新登录过程丢失用户输入。

**必要回归：** 首次过期请求就是写操作时，也能进入重新登录流程并保留草稿。

**证据：** 前端定向复现 F05。

### R16 · P2：新机器按说明配置共享密码，会找不到 mesh_app 模块

**位置：** `platform/README.md:84`、`docs/SETUP_GUIDE.md:64`。

安装说明只执行 `pip install -r platform/requirements.lock`，没有安装项目自身。从仓库根目录执行文档中的 `python -m mesh_app.auth` 时，包在 `platform/` 子目录，密码命令却没有设置 PYTHONPATH。完成说明中的依赖安装仍不足以使该模块可导入。

当前开发虚拟环境额外安装了 editable 项目，掩盖了问题。本次排除 editable `.pth`、保留普通依赖路径后，验证到 starlette 已安装但 mesh_app 不可导入；这不是一次全新联网安装验收。

**修复：** 密码命令前与既有启动/备份流程一致地加入 `$env:PYTHONPATH = (Resolve-Path platform).Path`，或从 platform 目录执行正确相对命令；同步两个使用文档和 `.env.example` 的密码生成示例。

**必要验收：** 不依赖开发机额外 editable 安装，仅按文档步骤可运行密码生成模块。

**证据：** `runs/review_20260912/frontend/findings.md` 的 F06。

# 基于 `2b325e9` 的网格生成修复方案

## 1. 目标与已确定的契约

本轮覆盖 **CR-01～CR-11、D-01，以及 D-02 的最小运行证据**。当前代码与评审提交一致；已通过源码核对主要调用链，并使用实际质量模块复现四种非法指标被判 PASS 的情况。本轮尚未修改文件，也未运行完整测试或真实网格验收。

按已确认的选择，统一以下语义：

| 情况 | 处理方式 |
|---|---|
| 进程正常结束、执行证据完整、本次必需网格存在 | 网格运行 `SUCCEEDED` |
| 缺少完成标记、控制执行事件缺失或冲突 | 网格运行 `FAILED` |
| setter 已执行，但 getter 报错或回读不匹配 | 保留生成成功，单独标记控制验证异常，允许继续创建分支 |
| 合法控制没有 getter | 标记不可回读验证，保留调用结果 |
| 指标缺失或非法 | 质量 `UNKNOWN` |
| 指标有效但违反硬阈值 | 质量 `FAIL`，保留有效实验记录 |
| 后处理失败或超时 | 仅影响后处理及预览状态 |

接口采用以下最小扩展：

- 运行摘要升级为 **Schema v4**，保留现有字段，增加运行身份、执行证据、控制验证、质量数据校验和来源信息。
- 控制预检响应增加 `effective_availability`，按 `key + selector` 返回草稿生效后的可编辑状态及原因。
- 运行详情增加后处理状态，以及带原因的样本资格判定；资格仅表示可用于“参数—质量观测”数据整理。
- 历史摘要继续可读，缺失的新证据显示为未知，不自动认定合格。
- 保持五个核心模块的扁平结构、CLI 的 Python ≥3.7 标准库边界，以及平台独立的依赖环境。

## 2. 修复结果可信性：CR-01～03、D-02

**CR-01：独占运行目录，明确产物归属。**

- 默认目录采用时间戳加 UUID；平台向 CLI 传入同一个 `run_id`，避免平台身份与摘要身份分离。
- runner 在复制输入、写脚本之前，通过排他创建的占用标记取得目录所有权；标记保留，已执行或 dry-run 使用过的目录均不能再次执行。
- 显式输出目录允许不存在或为空。兼容 Worker 预先写入的两份日志；Worker 自身必须先独占创建目录，再打开日志，避免覆盖历史日志。
- 历史产物目录和并发占用均明确拒绝，作为输入错误返回退出码 2，保留已有文件。
- 以原子写入的运行摘要记录本次完成阶段及输出清单、相对路径和大小。成功产物登记依据该清单；失败运行仍保留诊断材料。
- 保持 `.igg` 为现有最低产物要求；CGNS 缺失单独记录，并使预览不可用。

**CR-02：校验事件协议，分开记录调用与回读结果。**

- 为完成事件和控制事件补充运行身份、阶段信息。每个计划控制必须有唯一且匹配的应用事件、生成后观察事件。
- 缺失、损坏 JSON、重复 ID、未知 ID、目标或阶段不匹配进入明确协议错误；不得通过字典覆盖或解析时跳过而丢失错误。
- 即使没有请求控制，也必须收到本次脚本的最终完成事件。
- 每项控制增加 `VERIFIED`、`MISMATCH`、`READBACK_ERROR`、`UNVERIFIABLE` 验证结果，保留原始回读和错误。
- 比较以注册表及实际 API 值为依据：整数、布尔和枚举归一化后精确比较；浮点采用 `rel_tol=1e-7`、`abs_tol=1e-10`，长度统一换算到 SI 后比较。
- 厂商重采样或特殊枚举只有在存在已确认规则时才作对应归一化；无法解释的回读不认定为已验证。setter 前的回读失败仅作诊断。

**CR-03：先验证指标，再应用质量阈值。**

- 同时修复报告解析、CGNS 降级解析和直接调用 `evaluate_quality()` 的入口，去除计数字段的 `int(float(...))` 截断路径。
- 点数、层级必须为正整数；负体积单元数必须为非负整数；拒绝布尔计数。
- 检查所有已提供的质量统计值：实数有限、角度在 `[0, 180]`、比例为正、壁面距离非负。保持现有硬阈值及等号行为。
- 非法数据返回 `UNKNOWN`、`accepted=false`，原因包含字段位置。非有限值在对外结构中转换为 `null`，同时保留错误说明和原始报告。
- 摘要及相关持久化 JSON 使用 `allow_nan=False`，作为领域校验后的序列化保护。

**D-02：补齐来源，明确数据资格。**

- 记录输入摘要、实际执行源码签名、Git 提交及工作区修改状态、生成脚本摘要、控制注册表签名、质量规则版本、单位契约和可获取的厂商版本。
- 复用现有源码签名算法及平台产物哈希登记；生产代码不从测试模块导入函数，完整坐标指纹继续按需生成。
- 分别记录入队和执行时的来源。出现版本变化时保留运行结果并明确标记差异，降低样本资格。
- 样本资格由运行详情根据不可变摘要和已登记产物计算：执行证据完整、控制验证充分、质量可判定、来源完整且产物已登记时才合格。质量 `FAIL` 可以作为有效失败经验。
- 明确 `parent_run_id` 表示决策和比较关系；每个节点仍从几何及完整控制快照重新生成。专家满意标记保持独立。
- 本轮不增加训练集导出、自动标注或训练流水线。

## 3. 修复调度与资源问题：CR-04、07～09

**CR-04：后处理进入独立、可终止的子进程。**

- 将产物散列登记、预览转换移出主轮询循环；成功和失败运行的产物登记都走该通道。
- 后处理固定单并发，使用现有进程树管理能力启动和终止；主循环持续处理网格进程、超时、心跳、停止和新任务领取。
- 通过现有迁移机制增加后处理状态、起止时间及错误字段，状态为 `PENDING/RUNNING/COMPLETED/FAILED`，保持网格终态不可变约束。
- 后处理默认超时 **600 秒**，支持环境变量调整；资源门控为活动后处理额外计入一份现有内存预留，默认 **2.5 GiB**。
- 启动恢复只恢复排队状态，不同步执行转换；中断的后处理重新排队，超时或转换失败则记录失败。
- 停止时终止后处理进程树并保留可恢复状态。移除仅为同步后处理续写心跳的辅助线程。
- 迁移时仅将已有未完成预览保留为待处理，已完成历史运行不批量重新散列或转换。

**CR-07：按请求规模读取和生成预览。**

- 切片直接读取 HDF5 平面：I 对应 `[:, :, i]`，J 对应 `[:, j, :]`，K 对应 `[k, :, :]`，再转换为现有平面坐标顺序。该方式使用 HDF5 hyperslab。[h5py 官方文档](https://docs.h5py.org/en/stable/high/dataset.html#reading-writing-data)
- 表面和线框读取边界平面；线段只枚举边界索引，并保留棱边去重及退化维度行为。包围盒改为分块归约。
- API 对同一切片缓存缺失请求共享生成结果；每个 API 进程最多执行一个转换任务，等待在异步层完成。
- 切片坐标和拓扑采用可计算大小的数组，生成前检查预算；默认工作内存预算 **512 MiB**，每个运行的切片缓存上限 **1 GiB**。超限拒绝新生成并返回明确原因，已存在缓存继续可读。
- CGNS 质量降级解析改为分块扫描，仅保留质量片段及所需计数，正确处理跨块标记。

**CR-08：卸载密码计算并限制并发。**

- 使用现有 AnyIO 线程执行能力和专用容量限制器执行 scrypt，默认最多 **2 个**并发校验，不占用 ASGI 事件循环。[Starlette 官方文档](https://starlette.dev/threadpool/)
- 保持现有登录响应、统一凭据错误和共享账号模型。
- 增加 HTTPS Cookie 的 `Secure` 配置，默认保持本机 HTTP 开发可用；部署文档明确 HTTPS 配置。

**CR-09：按保存的进程组身份清理 POSIX 后代。**

- 启动独立会话时保存 PGID；父进程退出后仍使用该身份清理。
- SIGTERM 后检查进程组，宽限期结束后对残余成员发送 SIGKILL。
- 正常关闭、超时、停止均使用幂等清理路径，限定在本程序创建的进程组内。
- Windows Job Object 行为保留，并单独验收。

## 4. 修复编辑与查看流程：CR-05～06、10～11、D-01

**CR-05：可编辑性由当前草稿决定。**

- 服务端基于“父快照＋草稿＋必要清除”计算 `effective_availability`，复用现有规则。
- API 响应白名单和前端类型同步扩展；前端只消费与当前草稿匹配的预检结果。
- 前置项可在同一草稿内解锁子项；撤销前置项后重新锁定，并正确展示 `required_clears`。
- 冻结和父运行状态限制继续独立生效。可定位的预检错误响应也返回有效的可编辑状态，便于修正草稿。

**D-01：分离启用条件和实验取值。**

- 按已确认的项目规则，优化子项要求 `optimization.steps > 0`；喉部子项要求 `throat_points > 0`，并保留已有拓扑条件。
- `200` 和 `9` 仅保留为 campaign 取值；建议值放在说明中。
- 依赖排序、Web 可编辑性、提交校验及必要清除统一使用启用规则。
- `200→100/300`、`9→7/11` 不清除仍有效的子项；变为零、清除或切换到不适用拓扑时才触发清除。
- CLI 保持现有默认值使用方式，不新增“所有前置项必须显式传入”的限制。

**CR-06：编辑时保留原始字符串。**

- 数值输入使用文本状态保存中间态；预检和提交前完整解析十进制数值。
- 支持科学计数法：`1e3→1000`、`+10→10`；整数要求 `Number.isSafeInteger`，`1.9` 和超安全整数明确报错。
- 空串、符号和未完成指数属于未完成输入，不转换成零，也不自动清除控制。
- 可解析的变更用于预检；任何本地非法或未完成输入均阻止提交。保留粘贴及输入法组合输入过程。

**CR-11：资源创建即登记清理责任。**

- effect 开始时建立幂等清理函数；每个 vtk 对象、监听器和订阅创建后立即登记。
- 初始化失败、请求失败、解析失败和卸载使用同一清理路径，并按依赖逆序释放。
- 使用 `AbortController` 取消资产请求；单个请求失败时取消同批剩余请求，迟到结果不更新已卸载组件。

**CR-10：普通测试使用可分发夹具。**

- 在 `geometries/` 提交小型合成样例，覆盖单排、多排、splitter、gap、fillet 和单位解析；调整忽略规则，仅放行这些夹具。
- 流式解析等普通测试改用合成样例；真实工程几何测试使用独立集成入口，缺失文件时明确跳过并说明路径。
- 保持根单元测试可使用标准库 `unittest` 执行，无需 NUMECA、私人几何或平台依赖。

## 5. 实施顺序、验收与交付

按以下顺序实施，每批完成对应回归后再进入下一批：

| 批次 | 修复内容 | 核心验收 |
|---|---|---|
| ① 测试基线 | CR-10及必要回归夹具 | 仅有仓库文件的环境可执行根单元测试 |
| ② 结果契约 | CR-01～03、D-02 | 旧目录及同目录并发被拒绝；缺失、损坏、重复、错目标事件不能成功；回读异常独立记录；非法质量数值不 PASS |
| ③ 调度与资源 | CR-04、07～09 | A 后处理阻塞时 B 仍按外层期限终止；停止可响应；重启可恢复；切片读取量随平面增长；并发登录不阻塞 health |
| ④ 交互与领域 | CR-05～06、11、D-01 | 同草稿解锁与撤销正确；整数不截断；过期预检不生效；异常和取消路径完整释放 vtk 资源 |
| ⑤ 依赖与实机验收 | 依赖更新、文档和受控运行 | 前端构建及交互通过，代表性 AutoGrid 运行和平台闭环完成 |

补充验收要求：

- **质量测试**覆盖 NaN、±Inf、指数溢出、零/负点数、小数及布尔计数、非法角度/比例、缺字段和硬阈值等号。
- **预览测试**覆盖三个轴的首尾切片、非对称尺寸、退化维度、小网格拓扑一致性、同请求只生成一次、资源和缓存超限。
- **进程测试**在 Linux 验证父先退出、后代忽略 SIGTERM、正常结束后残余后代及重复清理；Windows 验证实际 Job Object 清理。
- **实机测试**验证默认基线，以及优化步数 `100/300`、喉部点数 `7/11` 的代表性组合。检查调用、回读及质量记录，不要求每个实验组合质量 PASS。
- 对代表性 CGNS 记录一次峰值内存和耗时，核对预算；不扩展成全量 344 项 campaign。
